# PLAN: Canopy clear wins

## Description

This plan records every change in the canopy workspace that passes the clear-win test. Live code,
consumers, or a counted cost prove the problem. The change improves one or more qualities and
degrades none. It fits the settled zero-compatibility and minimal-surface intent. The repository
can prove the result. Sixteen bounded read-only sweeps covered every hand-written area
once at commit `a5db5873`. The 196 items below are each one independent change. Items marked `Capability`
remove public surface with zero in-repo consumers. They follow settled intent, and the user can
veto each one in `Open Decisions`.

## Scope

- Tree state: `main` at `a5db5873`, working tree clean. Line numbers refer to that tree.
- Swept: every `.rs` file under `crates/`, `examples/`, and `xtask/` (63,635 lines), the Luau
  sources (`crates/canopy/luau/preamble.d.luau`, `crates/canopy-widgets/tests/luau/*.luau`,
  `examples/todo/smoke/**/*.luau`), every `Cargo.toml`, `.cargo/config.toml`, `clippy.toml`,
  `rustfmt-nightly.toml`, `rust-toolchain.toml`, `.gitignore`, `.github/workflows/ci.yml`,
  `README.md`, `AGENTS.md`, `api-surface/README.md`, and `docs/*.md`.
- Excluded: `api-surface/*.rs` (generated by ruskel 0.0.11, cited only as evidence),
  `Cargo.lock` (checked only for duplicate major versions), `target/`, `tmp/`, the untracked
  `vendor/mlua/target` leftover, image and font binaries (only their references were checked),
  and the sibling crates `ruau`, `tmcp`, `itty-core`, `itty-script` (read only for API facts).
- Compatibility stance: canopy has no backward-compatibility requirement. Public APIs, MCP
  payload shapes, Luau record fields, and CLI invocations may change. Remove obsolete surface
  outright and update every in-repo consumer in the same commit. Add no aliases or shims.
- Path convention: `core/X` means `crates/canopy/src/core/X`. `widgets/X` means
  `crates/canopy-widgets/src/X`. `examples/X` means `crates/examples/src/X`. `todo/X` means
  `examples/todo/X`. Other paths are repository-relative.
- Proof convention: each item names its focused checks. A change to a public surface also runs
  `cargo xtask api` and commits the regenerated skeleton. The stage gate is `cargo xtask tidy`
  and then `cargo xtask ci`. Zero-caller deletions prove themselves with
  `cargo check --workspace --all-targets --all-features`.
- Prior sweep: all 65 items of the previous `plans/wins.md` landed. Items below that finish a
  landed item say so.

### W2: Repaint the full row width after an interior line shift

- Outcome: Diff rendering leaves the same terminal state as a full repaint after a framed
  full-screen scroll.
- Evidence: `core/termbuf/mod.rs:673-687` `detect_inner_shift` fires when the outer ring is
  unchanged and rows `1..h-2` shifted. `render_shifted_rect` (`:761-781`) calls
  `backend.shift_lines(1, h-2, shift)` and repaints only columns `1..w-1` of the exposed rows
  (`:778`). The production backend scrolls the full terminal width (`core/backend/crossterm.rs:
  564-583` sets DECSTBM and emits `CSI n S`/`CSI n T`, which move every column and blank the
  vacated row). Result: the exposed row's cells at columns 0 and `w-1` stay blank, and side
  columns that are not vertically uniform shift by one row. `borders_match` (`:690-729`) checks
  only `prev == current` per cell. This contradicts `docs/architecture.md:151`. The only test,
  `diff_vertical_shift_uses_scroll_interior` (`core/termbuf/tests.rs:889-897`), records the call
  and models nothing. The unused `ReplayBackend` in the same file reproduces the mismatch: with
  `prev = ["#####","#abc#","#def#","#ghi#","#####"]` and
  `cur = ["#####","#xxx#","#abc#","#def#","#####"]`, replaying `cur.diff(&prev, ..)` over a
  rendered `prev` yields row 1 `" xxx "` instead of `"#xxx#"`.
- Change: In `render_shifted_rect` repaint each exposed row over the full buffer width
  (`render_line_range(backend, row, y, 0, width)`). In `detect_inner_shift` also require every
  interior row to share the same first and last cell, so a full-width scroll leaves the side
  columns unchanged. Add the replay test above.
- Constraints: `diff_vertical_shift_uses_scroll_interior` still expects `Some((1, 3, 1))` and one
  text op. Land before or with W176. Alternative: delete `detect_inner_shift` and
  `borders_match` (about 60 lines) and keep only the whole-buffer shift.
- Proof: The new replay test fails at HEAD and passes after.
  `cargo nextest run -p canopy -E 'test(diff_)'`.

### W3: Reject attaching the root under another node

- Outcome: `Core::attach` and `Core::set_children` refuse the root as a child instead of
  corrupting the tree.
- Evidence: `core/world/tree.rs:653-699` `attach_inner` and `:769-843` `set_children_inner`
  check `AlreadyAttached`, `WouldCreateCycle`, and `DuplicateChildKey`, but never
  `child == self.root`. With a detached `parent`, `is_ancestor_or_self(root, parent)` is false and
  root's parent is `None`, so `core.attach(detached, core.root)` succeeds and sets
  `root.parent = Some(detached)`. Only `validate_root` (`:372-381`) notices, through the debug
  assertion in `ensure_invariants` after the mutation. Release builds accept the edit until the
  next `update_layout` returns `Invariant("root node has a parent")` or `remove_subtree(detached)`
  deletes the root. `remove_subtree_inner` already guards the analogous case (`:853-855`). The
  paths are reachable through `Context::attach`, `Context::set_children_of`, and
  `Core::attach_keyed`.
- Change: After the `AlreadyAttached` check in `attach_inner`, and inside the validation loop of
  `set_children_inner`, return `Error::InvalidOperation("cannot attach root as a child".into())`
  when `child == self.root`. Add a unit test in `core/world/tests.rs` that creates a detached
  parent, asserts both edits fail, asserts `core.nodes[core.root].parent.is_none()`, and asserts
  `validate_invariants()` passes. Optionally let `tree_mutation_strategy` produce the root as an
  `Attach` child.
- Constraints: `WouldCreateCycle { parent, child }` is an acceptable variant choice. Scripts do
  not reach `attach` or `set_children` (0 hits under `core/script/`).
- Proof: The new test panics at HEAD on the debug assertion and passes after.
  `cargo nextest run -p canopy -E 'test(attach_rejects_root_as_child) | test(random_tree_mutations_preserve_invariants)'`.

- Constraints: Shift is still accepted, so uppercase input works.
